# AIL 0.1.1 — язык для машинного построения программ

Рабочий эксперимент: программа хранится как структурированный SSA-граф в JSON,
проходит проверку и компилируется в **статический ELF для Linux x86-64**.
Этот ELF запускается без Python, LLVM и стандартной библиотеки C.

Компилятор написан на Python. Выбор инструкций, стековые кадры, передача аргументов,
переходы и Linux syscalls реализованы собственным backend. GNU `as` кодирует
assembly в машинные байты, GNU `ld` создаёт ELF. Собственного кодировщика x86 и
ELF writer в этой версии нет.

Цель — проверить, удобнее ли ИИ создавать и изменять проверяемый граф, чем обычный
исходный текст. Преимущество пока **не измерено**. Формат не меняет устройство
модели: я по-прежнему передаю JSON через текстовые инструменты. JSON тоже требует
корректного синтаксиса; мы убираем необходимость в отдельной грамматике языка,
а не возможность любых ошибок.

## Установка

```bash
sh install.sh
export PATH="$HOME/.local/bin:$PATH"
ail doctor
AIL_EXAMPLES=$(ail examples)
ail run "$AIL_EXAMPLES/hello.ail.json"
```

Подробности установки, обновления и удаления: [INSTALL.md](docs/INSTALL.md).
Подготовка GitHub и релизов: [GITHUB.md](docs/GITHUB.md).
Инструкция для других ИИ: [AI_GUIDE.md](docs/AI_GUIDE.md).

## Быстрый запуск

Требуются Python 3.10+ и GNU binutils. Для запуска скомпилированных программ нужна
Linux x86-64. Проверка графа и интерпретатор используют только стандартную библиотеку
Python. Внешних Python-пакетов нет; установка проекта через pip необязательна.

В Ubuntu/Debian, если зависимости отсутствуют:

```bash
sudo apt install python3 binutils
```

Из каталога проекта:

```bash
python3 -m ail check examples/hello.ail.json
python3 -m ail compile examples/hello.ail.json -o build/hello
./build/hello
```

Вывод:

```text
Hello from AIL!
```

В релизном tar.gz также есть уже собранный `prebuilt/hello-linux-x86_64`.
После распаковки при необходимости выдай ему разрешение:

```bash
chmod +x prebuilt/hello-linux-x86_64
./prebuilt/hello-linux-x86_64
```

## Что работает

- Типы `i64`, `i1`, `ptr`; неизменяемые UTF-8 globals.
- 20 операций и три вида терминаторов: `ret`, `jump`, `branch`.
- Функции, до шести аргументов, рекурсия, условия и циклы.
- Параметры блоков вместо отдельных phi-инструкций; одновременная передача значений.
- Строгая проверка структуры, типов, CFG, SSA dominance и объявленных эффектов.
- Вывод текста и явно помеченные низкоуровневые Linux syscalls.
- Ограниченный эталонный интерпретатор для сравнения результатов.
- Правки функций и инструкций по ID с контрольной суммой исходного графа.
- Структурная JSON Schema для редакторов и генераторов.

Программа не переводится в C, Rust или LLVM IR. Путь сборки:

```text
JSON graph → verification → x86-64 assembly → GNU as → GNU ld → ELF
```

## Команды

| Команда | Назначение |
|---|---|
| `python3 -m ail check INPUT` | Проверить весь граф |
| `python3 -m ail compile INPUT -o OUTPUT` | Создать ELF |
| `python3 -m ail emit INPUT -o OUTPUT.s` | Сохранить assembly |
| `python3 -m ail run INPUT --timeout 5` | Собрать временный ELF и запустить |
| `python3 -m ail interpret INPUT --max-steps 1000000` | Выполнить через интерпретатор |
| `python3 -m ail fmt INPUT -o OUTPUT` | Проверить и канонически записать JSON |
| `python3 -m ail fingerprint INPUT` | Получить SHA-256 канонического JSON |
| `python3 -m ail patch INPUT PATCH -o OUTPUT` | Проверить и применить изменения |

`run` и `interpret` возвращают код AIL-программы, поэтому ненулевой код может быть
результатом вычисления. Например, factorial возвращает 120, arithmetic — 42.
Ошибка CLI возвращает 2; арифметическая ловушка — 125. Эти коды не зарезервированы:
сама программа тоже может вернуть 2 или 125.

## Примеры

| Файл в `examples/` | Что проверяет | Результат / код процесса |
|---|---|---|
| `hello.ail.json` | Вывод текста | `Hello from AIL!`, код 0 |
| `arithmetic.ail.json` | Вызов функции и умножение | 42 |
| `factorial.ail.json` | Цикл с параметрами блоков | 120 |
| `fibonacci.ail.json` | Несколько значений на переходе | 55 |
| `swap.ail.json` | Обмен параметров на петле | 21 |
| `recursion.ail.json` | Рекурсивные вызовы | 120 |
| `six_args.ail.json` | Шесть аргументов функции | 21 |
| `syscall.ail.json` | `addr` и raw Linux write syscall | `Raw syscall`, код 0 |

Интерпретатор захватывает stdout/stderr и не исполняет raw `syscall`; этот пример
проверяется только нативно. `write` использует длину UTF-8 в байтах автоматически.

## Локальное изменение графа

Готовая правка `examples/arithmetic.patch.json` меняет константу `a` с 6 на 8:

```bash
python3 -m ail patch examples/arithmetic.ail.json examples/arithmetic.patch.json -o build/arithmetic56.ail.json
python3 -m ail interpret build/arithmetic56.ail.json
echo $?
```

Получится код 56 (`8 × 7`); исходный файл остаётся прежним. Название выходного
файла можно выбрать любое. Патч адресует инструкцию `a` в блоке `entry` функции
`main`. Устаревшая контрольная сумма или невалидная правка отклоняются до записи.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Для компилятора прошёл 41 тест, включая 350 сравнений арифметики с нативным
исполнением. В этих проверках сравниваются все 64 бита внутри исполняемой программы,
а не только младший байт кода завершения. Отдельно проверяются циклы, рекурсия,
параллельная передача параметров, отрицательное деление, переполнение, UTF-8,
недопустимые графы и откат правок. Подробности — `docs/VALIDATION.md`.

## Границы версии

Это прототип, не универсальная замена существующим языкам. Сейчас нет floating
point, heap, изменяемых массивов, структур, FFI, Windows backend, оптимизатора,
debug information и self-hosting. `ptr` указывает на начало неизменяемой global;
арифметики указателей и `load`/`store` пока нет.

Все SSA-значения размещаются в стековых слотах. Это упрощает проверку backend,
но не обеспечивает производительность оптимизирующих компиляторов. Компилируется
весь модуль; частичной перекомпиляции пока нет. `effects` — статические объявления,
не sandbox и не доказательство безопасности программы. Raw syscalls имеют
полномочия запущенного процесса. Рекурсия нативной программы ограничена системным
стеком; только интерпретатор имеет отдельные ограничения глубины и шагов.

## Структура

- `ail/verify.py` — проверка структуры, типов, эффектов и SSA.
- `ail/x86.py` — backend и атомарная сборка ELF.
- `ail/interpreter.py` — эталонная семантика.
- `ail/edit.py` — канонический формат и проверяемые правки.
- `ail/cli.py` — командный интерфейс.
- `ail.schema.json` — структурная схема; не заменяет семантическую проверку.
- `examples/` — готовые графы и патч.
- `tests/` — проверка backend и ошибок языка.
- `docs/SPEC.md` — семантика AIL v1.
- `docs/ROADMAP.md` — следующий этап и критерии проверки идеи.
- `prebuilt/` — демонстрационный ELF и его assembly.
