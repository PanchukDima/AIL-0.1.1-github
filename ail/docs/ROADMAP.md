# Следующий этап

## 0.2: работа с данными

Сначала добавить `u8`, буферы с длиной, проверяемые `load`/`store`, целочисленные
преобразования и небольшой runtime для вывода чисел и обработки argv. Сохранить
одинаковые правила переполнения, диапазонов и ошибок в интерпретаторе и backend.
Проверка этапа: программа читает аргумент, считает результат и печатает его;
невалидный индекс вызывает определённую языком ошибку в обоих исполнителях.

## Проверить гипотезу удобства для ИИ

До расширения языка выбрать одинаковые задачи для AIL и одного обычного языка:
арифметический CLI, обработка массива, небольшая правка алгоритма. Зафиксировать
используемую модель, инструменты, лимит контекста и число попыток. Измерять:

- долю успешных программ по независимым проверкам;
- количество токенов создания и изменения программы;
- число ошибок типов, связей графа и логики;
- размер области правки и число повторных генераций;
- время сборки, скорость исполнения и размер бинарника.

Сейчас результаты таких сравнений отсутствуют. SSA-граф может уменьшить ошибки
связей, но многословный JSON способен увеличить расходы токенов. Возможное
следующее представление — компактные массивы операций с той же канонической
моделью, а не преждевременная замена JSON бинарным форматом.

## Backend после измерений

Добавить constant folding, удаление неиспользуемых pure-вычислений и распределение
регистров. Любую оптимизацию проверять против интерпретатора на граничных значениях
и случайных графах. Затем добавить LLVM backend для проверки независимости IR
и качества кода либо собственные x86 encoder и ELF writer, если целью останется
минимальная внешняя toolchain. Не объединять эти цели в один большой этап.

## Более поздние возможности

FFI и библиотеки, floating point, несколько архитектур, binary serialization,
инкрементальная сборка, debug mapping на ID, отдельная модель безопасной памяти.
Self-hosting возможен только после достаточного runtime; он не является свойством
текущей версии.
