# Установка AIL 0.1.1

Поддерживаемая среда установки и нативного исполнения — **Linux x86-64**,
Python 3.10+ и GNU binutils (`as`, `ld`). На Windows используй Linux в WSL2 x86-64.
На ARM и macOS этот установщик не выполняет нативную установку.

## Установка для текущего пользователя

Распакуй релизный архив или клонируй исходники, затем из корня проекта:

```bash
sh install.sh
export PATH="$HOME/.local/bin:$PATH"
ail --version
ail doctor
AIL_EXAMPLES=$(ail examples)
ail run "$AIL_EXAMPLES/hello.ail.json" --timeout 5
```

Результат последней команды — `Hello from AIL!`. Установщик сам проверяет
нативный пример до переключения команды `ail` на новую версию.
Он не скачивает пакеты, не вызывает pip и не использует sudo.

Если отсутствуют системные зависимости, на Ubuntu/Debian установи их отдельно:

```bash
sudo apt install python3 binutils
```

Команда устанавливается в `~/.local/bin/ail`. Код, схема, примеры, документация
и скрипты удаления копируются в `~/.local/share/ail/versions/…`. Исходный каталог
после успешной установки можно переместить: установленная программа автономна
от этой копии исходников, но для компиляции ей по-прежнему нужен Python и binutils.

Чтобы `ail` была доступна после нового входа в систему, добавь в свой профиль
оболочки строку:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Установщик не редактирует настройки оболочки автоматически. До добавления PATH
можно вызывать команду полным путём: `"$HOME/.local/bin/ail" doctor`.

## Выбор каталога и интерпретатора

```bash
sh install.sh --prefix "$HOME/apps/ail"
export PATH="$HOME/apps/ail/bin:$PATH"
```

Для установки с конкретным интерпретатором:

```bash
AIL_PYTHON=python3.12 sh install.sh
```

Установленная команда использует `python3` из PATH. Этот runtime тоже должен
иметь версию 3.10+. Для системной установки поддерживается `--prefix /usr/local`,
но запись туда требует прав администратора; установка в домашний каталог —
обычный рекомендуемый вариант.

## Обновление

Скачай новую версию исходников и снова выполни `sh install.sh` с тем же `--prefix`.
Команда `ail` переключается атомарно после проверки нового кандидата. Предыдущие
установленные версии сохраняются до удаления продукта. Повторная установка
тех же файлов повторно использует ту же проверенную копию.

Если установленная копия была изменена вручную, установщик сообщает об этом
и не перезаписывает изменения. Сохрани нужные изменения отдельно, затем удали
старую установку и установи исходники снова. Пользовательские `.ail.json` храни
в своих рабочих каталогах, не внутри каталога установленных версий.

## Удаление

Из каталога исходников:

```bash
sh uninstall.sh
```

Для нестандартного пути используй тот же prefix:

```bash
sh uninstall.sh --prefix "$HOME/apps/ail"
```

Можно удалить продукт и без исходного checkout, используя установленный скрипт:

```bash
AIL_EXAMPLES=$(ail examples)
sh "$(dirname "$AIL_EXAMPLES")/uninstall.sh"
```

При нестандартной установке добавь её `--prefix`. Удаляются команда и версии,
учтённые установщиком; другие программы в каталоге `bin` и исходные файлы проекта
сохраняются. Небольшие служебные файлы установки остаются для повторной установки
и согласованного выполнения операций. Удаление ещё раз допустимо.

Если существующая команда `ail` или каталог установки принадлежат другой
программе, установщик отказывается заменять их. Выбери другой prefix.

## Альтернативная установка Python-пакета

В выделенное окружение из checkout:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/ail doctor
AIL_EXAMPLES=$(.venv/bin/ail examples)
.venv/bin/ail run "$AIL_EXAMPLES/hello.ail.json"
```

Этот путь может скачивать build dependencies. Для офлайн-установки основным
вариантом является `install.sh`. Wheel содержит примеры, схему и документацию.
Удали pip-установку через `.venv/bin/python -m pip uninstall ail-prototype`;
`uninstall.sh` обслуживает только собственные установки AIL.
