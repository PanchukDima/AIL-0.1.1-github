# AIL: инструкция для ИИ-разработчика

**Целевая реализация:** AIL 0.1.1, формат программы `version: 1`.
**Нативная платформа:** Linux x86-64.
**Комплект:** `исходный репозиторий или релизный архив AIL 0.1.1` и этот файл.

Передай другому ИИ этот документ вместе с архивом компилятора. Документ содержит
готовую инструкцию для агента, точный формат программы, рабочие примеры и порядок
проверки. Для запуска нужен доступ к файлам и командной строке. ИИ без таких
инструментов может создавать графы, но должен обозначать их как непроверенные.

AIL — обычный инструмент генерации программ. Он не меняет веса или внутреннее
представление ИИ. Основное представление программы — JSON-граф; компилятор
самостоятельно генерирует x86-64 assembly, затем использует GNU `as` и `ld`.

## 1. Готовая инструкция агенту

Следующий блок можно включить в системные или проектные инструкции другого ИИ.
Передай ему также остальные разделы этого документа: один этот блок не содержит
полной спецификации формата.

```text
Ты разрабатываешь программы на AIL 0.1.1 (формат version: 1).
Прочитай AIL_AI_GUIDE.md; при расхождении с ним проверь реализацию
компилятора и docs/SPEC.md. Не придумывай неподдерживаемые инструкции.

Основной исходный код — структурированный SSA-граф в JSON. Создавай
полные валидные объекты, а не псевдокод и не текстовую LLVM-подобную запись.
Используй только i64, i1 и ptr. Все вычисляемые значения имеют уникальные
ID внутри функции. Операнды — ссылки на ID без префикса %. Литералы
оформляй отдельными const-инструкциями. Не добавляй неизвестные поля.

Входная функция не имеет аргументов и возвращает i64. Первый блок — входной,
без параметров блока. Его нельзя использовать как цель перехода.
Каждый блок заканчивается одним ret, jump или branch. Все блоки достижимы.

Передавай состояние циклов и результаты ветвей через параметры блоков.
У определения каждого значения должна быть доступность на всех путях
к использованию (dominance). select выбирает уже вычисленные значения;
для условных вызовов и вывода используй branch.

Функции с write объявляют io. Raw syscall требует io и unsafe.
Вызывающая функция объявляет эффекты вызываемых функций.
Используй write для вывода статического UTF-8 global.

Рабочий цикл: создать граф → ail check → interpret при отсутствии syscall
→ compile → нативное исполнение с timeout → сравнить результат с требованиями.
Проверка типов не доказывает правильность алгоритма. Ненулевой exit code
может быть результатом программы. Полный i64 нельзя проверить только по
exit code: используй значение интерпретатора и нативное сравнение внутри графа.

Для изменения существующей инструкции сохраняй ID. Получи свежий fingerprint,
создай patch с expected_sha256 и проверь результат. Для связанных изменений,
которые временно нарушают корректность графа, замени всю функцию.

Не изменяй компилятор для обхода диагностики. Если задача требует отсутствующих
возможностей, укажи конкретное ограничение и согласуй изменение объёма задачи.
Если запуск недоступен, выдай исходный граф и команды проверки; не утверждай,
что сборка или тесты выполнены.

В ответе укажи созданные файлы, команды запуска, фактически полученные результаты
проверок и ограничения. Не называй неоптимизированный прототип быстрее или
удобнее существующих языков без измерений.
```

## 2. Подготовка среды

Распакуй исходники или клонируй репозиторий. Все команды далее выполняются из корня проекта. Установка описана в `docs/INSTALL.md`: после неё также доступны команды `ail doctor` и `ail examples`.
Нужны Python 3.10+ и GNU binutils. Внешние Python-библиотеки не требуются.
Компиляция использует `as` и `ld`, запуск бинарников требует Linux x86-64.

```bash
cd ail
python3 --version
python3 -m ail --version
python3 -m ail check examples/hello.ail.json
```

Ожидаемая версия компилятора — `0.1.1`. Если зависимости отсутствуют,
на Ubuntu/Debian команда установки — `sudo apt install python3 binutils`.
Сначала установи, какой каталог проекта и какие инструменты реально доступны.

| Команда | Назначение |
|---|---|
| `python3 -m ail check app.ail.json` | Проверить структуру, типы, CFG, SSA и эффекты |
| `python3 -m ail interpret app.ail.json --max-steps 1000000` | Эталонное исполнение с ограничением шагов |
| `python3 -m ail compile app.ail.json -o build/app` | Собрать статический ELF |
| `python3 -m ail run app.ail.json --timeout 5` | Собрать временный ELF и запустить с timeout |
| `python3 -m ail emit app.ail.json -o build/app.s` | Получить assembly для диагностики |
| `python3 -m ail fmt app.ail.json -o build/app.canonical.json` | Канонически записать проверенный граф |
| `python3 -m ail fingerprint app.ail.json` | SHA-256 канонического графа |
| `python3 -m ail patch app.ail.json change.json -o build/app.next.ail.json` | Применить проверяемую правку |

`check`, успешные `compile`, `fmt` и `patch` возвращают 0. `run` и `interpret`
возвращают код самой программы. Ошибки выполнения команды обычно возвращают 2;
арифметическая ловушка — 125. Сама программа тоже может вернуть эти значения:
учитывай stderr и ожидаемый результат, а не только код.

## 3. Формат графа

| Объект | Обязательные поля |
|---|---|
| Модуль | `version`, `entry`, `globals`, `functions` |
| Global | `id`, `text` |
| Функция | `id`, `params`, `return`, `effects`, `blocks` |
| Параметр функции или блока | `id`, `type` |
| Блок | `id`, `params`, `instructions`, `term` |
| Инструкция | `id`, `op`, `type` и поля конкретной операции |

Неизвестные поля запрещены. Не добавляй в граф `description`, `comment`,
`metadata`, `requires`, `ensures` и другие произвольные аннотации.
Комментарии и объяснения помещай в отдельный Markdown, JSON-комментариев нет.
Нельзя повторять ключи JSON-объекта.

Правила ID:

- Только ASCII: `[A-Za-z_][A-Za-z_0-9]*`. Примеры: `main`, `loop`, `next_sum`.
- Функции уникальны в модуле; globals уникальны в своём пространстве модуля.
- Блоки уникальны внутри функции.
- Параметры функции, параметры всех блоков и результаты всех инструкций
  имеют **общую область уникальности внутри функции**.
- В разных функциях одинаковые ID значений допустимы.
- Ссылки — строки вида `"next_sum"`; не `"%next_sum"` и не `"@main"`.

Типы:

| Тип | Правила |
|---|---|
| `i64` | Знаковое 64-битное целое; литерал от `−2^63` до `2^63−1` |
| `i1` | Boolean; литералы JSON `true` и `false` |
| `ptr` | Адрес начала неизменяемого global, полученный через `addr` |

Неявных преобразований нет. Нельзя заменить `i64`-литерал на `true` или
`i1`-литерал на `1`. Параметры и return функций используют эти три типа.
Входная функция, указанная в `entry`, должна иметь `params:[]` и `return:"i64"`.

## 4. Все поддерживаемые инструкции

В таблице не повторяются общие поля `id`, `op`, `type`. `args` содержит ID значений,
а не литералы. Для обычных бинарных операций нужны ровно два аргумента.

| `op` | Дополнительные поля | Операнды → результат |
|---|---|---|
| `const` | `value` | Литерал → `i64` или `i1` |
| `add`, `sub`, `mul` | `args:[a,b]` | `i64,i64 → i64` |
| `sdiv`, `srem` | `args:[a,b]` | `i64,i64 → i64` |
| `and`, `or`, `xor` | `args:[a,b]` | Одинаковый `i64` или `i1` → тот же тип |
| `eq`, `ne` | `args:[a,b]` | Одинаковый `i64` или `i1` → `i1` |
| `slt`, `sle`, `sgt`, `sge` | `args:[a,b]` | Знаковое сравнение `i64,i64 → i1` |
| `select` | `cond`, `yes`, `no` | `cond:i1`; варианты одного типа → тот же тип |
| `call` | `function`, `args` | Аргументы по сигнатуре функции → её return |
| `addr` | `global` | ID global → `ptr` |
| `write` | `global`, `fd` | ID global и `fd:i64` → `i64`, эффект `io` |
| `syscall` | `number`, `args` | `number:i64`, до 6 `i64`/`ptr` → `i64` |

Это **20 операций**, без псевдонимов. `div`, `cmp`, `phi`, `print`, `exit`,
`alloc`, `load`, `store`, `cast` и текстовый `while` не поддерживаются.

Пример одной инструкции сложения:

```json
{"id":"sum","op":"add","type":"i64","args":["left","right"]}
```

`left` и `right` должны быть определены ранее и иметь тип `i64`.
`add`, `sub`, `mul` переполняются по модулю `2^64` с интерпретацией результата
как знакового числа. Литералы за пределами диапазона запрещены.

`sdiv` округляет к нулю. `srem` равен `a − quotient × b` и имеет знак делимого
или равен нулю. Деление на ноль и пара `−2^63, −1` вызывают ловушку с кодом 125
для обеих операций.

`select` выбирает между **уже вычисленными** значениями. Если инструкция,
создающая один из вариантов, выполняет вывод, этот вывод уже произошёл.
Для условного выполнения используй разные блоки и `branch`.

## 5. Блоки, ветвления и циклы

Первый блок функции — входной. Его `params` пусты. Переходы в него запрещены.
Все остальные блоки должны быть достижимы. После массива инструкций стоит
один терминатор:

```json
{"op":"ret","value":"answer"}
```

```json
{"op":"jump","target":"loop","args":["next_n","next_sum"]}
```

```json
{
  "op":"branch",
  "cond":"done",
  "then":{"target":"exit","args":["sum"]},
  "else":{"target":"body","args":["n","sum"]}
}
```

Число и типы аргументов каждого ребра должны совпадать с параметрами цели.
`branch.cond` имеет тип `i1`. Аргументы доступны в исходном блоке.
При переходе параметры назначения получают значения одновременно:
переход `[b,a]` на параметры `[a,b]` корректно обменивает их местами.

Каждое значение определяется статически один раз. Чтобы изменить состояние
цикла, создай новые результаты инструкций и передай их параметрами следующей
итерации. Внутри цикла одно статическое определение выполняется многократно.

Определение должно находиться на каждом пути к использованию. Параметры функции
доступны во всех блоках. Значение из одной ветки нельзя использовать после
слияния напрямую: передай его параметром общего блока на каждом входящем ребре.
Не ссылайся вперёд на более позднюю инструкцию или на результат той же инструкции.

## 6. Пример: Hello World

Сохрани как `hello_agent.ail.json`. Это полный готовый граф:

```json
{
  "version": 1,
  "entry": "main",
  "globals": [{"id":"message","text":"Hello from another AI!\n"}],
  "functions": [
    {
      "id":"main",
      "params":[],
      "return":"i64",
      "effects":["io"],
      "blocks":[
        {
          "id":"entry",
          "params":[],
          "instructions":[
            {"id":"stdout","op":"const","type":"i64","value":1},
            {"id":"written","op":"write","type":"i64","global":"message","fd":"stdout"},
            {"id":"exit_code","op":"const","type":"i64","value":0}
          ],
          "term":{"op":"ret","value":"exit_code"}
        }
      ]
    }
  ]
}
```

```bash
python3 -m ail check hello_agent.ail.json
python3 -m ail interpret hello_agent.ail.json
python3 -m ail run hello_agent.ail.json --timeout 5
```

Оба исполнения выводят `Hello from another AI!` с переводом строки и возвращают 0.
`write` вычисляет длину UTF-8 global автоматически. NUL в конец не добавляется.
Этот минимальный пример не проверяет частичную запись: для требований надёжного
I/O нужно отдельно обрабатывать возвращаемое значение и учитывать ограничения
текущего runtime.

## 7. Пример: функция и ветвление

Сохрани как `max_agent.ail.json`. Функция `max_i64` выбирает максимум двух чисел:

```json
{
  "version":1,
  "entry":"main",
  "globals":[],
  "functions":[
    {
      "id":"main",
      "params":[],
      "return":"i64",
      "effects":[],
      "blocks":[
        {
          "id":"entry",
          "params":[],
          "instructions":[
            {"id":"left","op":"const","type":"i64","value":-7},
            {"id":"right","op":"const","type":"i64","value":3},
            {"id":"answer","op":"call","type":"i64","function":"max_i64","args":["left","right"]}
          ],
          "term":{"op":"ret","value":"answer"}
        }
      ]
    },
    {
      "id":"max_i64",
      "params":[{"id":"a","type":"i64"},{"id":"b","type":"i64"}],
      "return":"i64",
      "effects":[],
      "blocks":[
        {
          "id":"entry",
          "params":[],
          "instructions":[{"id":"take_a","op":"sge","type":"i1","args":["a","b"]}],
```

Это ожидаемое завершение данной программы, а не неуспешная сборка.

## 8. Пример: цикл и встроенная проверка результата

Сохрани как `sum_agent.ail.json`. Программа считает сумму `1 + … + 10`, сравнивает
все 64 бита результата с 55 и возвращает 0 при совпадении, 71 при ошибке:

```json
{
  "version":1,
  "entry":"main",
  "globals":[],
  "functions":[
    {
      "id":"main",
      "params":[],
      "return":"i64",
      "effects":[],
      "blocks":[
        {
          "id":"entry",
          "params":[],
          "instructions":[
            {"id":"zero","op":"const","type":"i64","value":0},
            {"id":"one","op":"const","type":"i64","value":1},
            {"id":"ten","op":"const","type":"i64","value":10}
          ],
          "term":{"op":"jump","target":"loop","args":["ten","zero"]}
        },
        {
          "id":"loop",
          "params":[{"id":"n","type":"i64"},{"id":"sum","type":"i64"}],
          "instructions":[{"id":"done","op":"eq","type":"i1","args":["n","zero"]}],
          "term":{"op":"branch","cond":"done","then":{"target":"exit","args":["sum"]},"else":{"target":"body","args":["n","sum"]}}
        },
        {
          "id":"body",
          "params":[{"id":"old_n","type":"i64"},{"id":"old_sum","type":"i64"}],
          "instructions":[
            {"id":"next_sum","op":"add","type":"i64","args":["old_sum","old_n"]},
            {"id":"next_n","op":"sub","type":"i64","args":["old_n","one"]}
          ],
          "term":{"op":"jump","target":"loop","args":["next_n","next_sum"]}
        },
        {
          "id":"exit",
          "params":[{"id":"total","type":"i64"}],
          "instructions":[
            {"id":"expected","op":"const","type":"i64","value":55},
            {"id":"matches","op":"eq","type":"i1","args":["total","expected"]},
            {"id":"bad","op":"const","type":"i64","value":71},
            {"id":"exit_code","op":"select","type":"i64","cond":"matches","yes":"zero","no":"bad"}
          ],
          "term":{"op":"ret","value":"exit_code"}
        }
      ]
    }
  ]
}
```

```bash
python3 -m ail check sum_agent.ail.json
python3 -m ail interpret sum_agent.ail.json --max-steps 1000
python3 -m ail run sum_agent.ail.json --timeout 5
```

Оба исполнения возвращают 0. Если заменить ожидаемое 55 на 54, оба должны
вернуть 71. Это полезная проверка того, что проверяющая часть программы работает.

## 9. Как проверять алгоритм

Сначала сопоставь задачу с возможностями AIL. Определи входы, результаты,
граничные значения, ожидаемые эффекты и условие завершения. Затем:

1. Создай граф и запусти `check`. Исправь структуру и типы до исполнения.
2. Для программ без raw `syscall` вызови интерпретатор с конечным бюджетом шагов.
3. Проверь полный результат через Python API `interpret(...).value`, когда
   программа непосредственно возвращает вычисленное число.
4. Собери и выполни нативную программу с timeout; сравни stdout, stderr и код.
5. Для значений вне диапазона 0…255 встрои в граф сравнение результата с ожидаемым
   `i64` и возвращай 0/ненулевой код проверки. Exit code содержит только 8 бит.
6. Проверь несколько независимых случаев и хотя бы одно неверное ожидание.
   Согласие интерпретатора и backend ещё не означает, что алгоритм решает задачу.

Пример проверки двух программ, где ненулевой результат намеренный:

```python
from pathlib import Path
import subprocess
from ail.verify import load, verify
from ail.interpreter import interpret
from ail.x86 import compile_native

for filename, expected_value, expected_stdout in [
    ("hello_agent.ail.json", 0, b"Hello from another AI!\n"),
    ("max_agent.ail.json", 3, b""),
    ("sum_agent.ail.json", 0, b""),
]:
    module = verify(load(filename))
    reference = interpret(module, max_steps=1000)
    assert reference.value == expected_value
    assert reference.stdout == expected_stdout
    assert reference.stderr == b""
    binary = compile_native(module, Path("build") / Path(filename).stem)
    native = subprocess.run([str(binary)], capture_output=True, timeout=5)
    assert native.returncode == reference.exit_code
    assert native.stdout == reference.stdout
    assert native.stderr == reference.stderr
print("All guide examples passed")
```

В задачах с делением отдельно тестируй ноль, отрицательные аргументы и MIN/−1.
Для рекурсивных функций проверяй базовый случай. Для циклов — ноль итераций,
одну и несколько. Интерпретатор ограничивает глубину вызовов значением 128;
нативное исполнение ограничено системным стеком.

## 10. Правки существующих программ

Сохраняй ID для неизменных узлов. Для одной инструкции используй
`replace_instruction`; для всей функции — `replace_function`. У patch нет
операций `add_node`, `remove_edge`, `append_instruction` или `replace_block`.

Следующий код создаёт готовый патч к примеру `max_agent.ail.json`:

```python
import json
from pathlib import Path
from ail.verify import load, verify
from ail.edit import fingerprint

module = verify(load("max_agent.ail.json"))
patch = {
    "expected_sha256": fingerprint(module),
    "edits": [{
        "op": "replace_instruction",
        "function": "main",
        "block": "entry",
        "id": "left",
        "value": {"id":"left","op":"const","type":"i64","value":12}
    }]
}
Path("max_change.json").write_text(
    json.dumps(patch, ensure_ascii=False, indent=2) + "\n", encoding="utf-8"
)
```

```bash
python3 -m ail patch max_agent.ail.json max_change.json -o build/max_agent.next.ail.json
python3 -m ail check build/max_agent.next.ail.json
```

Теперь результат изменённой программы — 12. Снова проверь его интерпретатором
и нативным запуском; исходная программа всё ещё возвращает 3.

Fingerprint нужно **получить из текущего графа**, а не выдумать или вставить из
другой версии. Это SHA-256 канонического JSON; обычный hash сырых байт файла
может отличаться. При `stale program fingerprint` перечитай текущую программу,
проверь, применима ли правка, и пересоздай patch.

Каждая правка сохраняет ID цели. Verifier проверяет граф после каждой операции
в `edits`. Если изменение типа нескольких инструкций создаёт невалидные
промежуточные состояния, сделай одну `replace_function` с полной корректной
функцией. CLI записывает результат только при успешной проверке. Это защита
от невалидной правки, но не механизм блокировки конкурентных писателей.

## 11. I/O и эффекты

`effects` — массив объявлений, не список разрешений ОС:

| Действие | Необходимые effects |
|---|---|
| Арифметика, сравнения, `addr` | `[]` достаточно |
| `write` | `["io"]` |
| Raw `syscall` | `["io","unsafe"]` |
| `call` | Все effects вызываемой функции должны присутствовать у вызывающей |

Нет effect `pure`: отсутствие эффектов записывается как `[]`.
Нет `extern`, автоматического libc, printf или динамических строк.

Для stdout используй `fd`-константу 1; для stderr — 2. `write` принимает ID global,
не указатель. Она делает одну запись и возвращает число байт или отрицательный
Linux errno; retry для EINTR/частичной записи не реализован. Интерпретатор
захватывает stdout/stderr в памяти и моделирует успешную запись; другие fd
считает закрытыми. Он не эмулирует произвольное состояние ОС.

Raw `syscall` используй только при необходимости низкоуровневого интерфейса
Linux x86-64. Номер — ссылка на `i64`, аргументы — до шести ссылок на `i64`/`ptr`.
Интерпретатор его не исполняет, поэтому требуется отдельная нативная проверка
конкретного системного вызова. `unsafe` не ограничивает полномочия процесса
и не предотвращает неверные адреса или длины. Рабочий пример есть в
`examples/syscall.ail.json`.

## 12. Исправление диагностики

| Сообщение | Что исправить |
|---|---|
| `unknown fields` | Удалить неподдерживаемые поля; описание вынести в Markdown |
| `duplicate SSA value` | Переименовать конфликтующий результат/параметр и все его ссылки |
| `undefined value` | Определить значение и проверить ID ссылки |
| `used before definition` | Переставить зависимые инструкции или передать значение параметром |
| `does not dominate use` | Передать результат ветви в параметр общего блока на каждом входе |
| `wrong argument count` | Согласовать аргументы call/перехода с сигнатурой цели |
| `has type … expected …` | Исправить операцию или тип; не вводить неявный cast |
| `unreachable blocks` | Удалить лишний блок либо добавить реальное достижимое ребро |
| `edges to the function entry block are forbidden` | Создать отдельный loop-блок |
| `requires declared effects` | Добавить нужные effects инструкции и вызываемых функций |
| `stale program fingerprint` | Перечитать текущую программу и пересоздать применимую правку |
| `interpreter exceeded step budget` | Проверить завершение; увеличить бюджет при обоснованном числе шагов |
| `reference interpreter does not execute raw syscalls` | Выполнить отдельную нативную проверку или заменить syscall на поддерживаемый write |
| `missing GNU as/ld` | Установить binutils или предоставить только непроверенный граф |

Не подавляй ошибку изменением verifier. Диагностика указывает функцию, блок,
инструкцию или место использования; начинай с этой области графа.

## 13. Ограничения и передача результата

В 0.1.1 отсутствуют floats, heap, изменяемые массивы, структуры, арифметика
указателей, `load`/`store`, FFI, runtime для argv и вывода чисел, optimizer,
Windows/ARM backend, debug info и инкрементальная компиляция.
Все SSA-значения backend размещает на стеке. Нет доказательства, что AIL сокращает
затраты токенов или повышает качество генерации по сравнению с обычными языками.

Сгенерированный ELF автономен; Python нужен компилятору и интерпретатору.
Источник истины программы — JSON-граф. Assembly и ELF — производные артефакты.
Не исправляй только assembly: изменение потеряется при следующей сборке графа.

Передавая результат пользователю или следующему агенту, приложи:

- исходный `.ail.json` и, если применялись изменения, patch;
- команду сборки и запуска из правильного рабочего каталога;
- фактические значения, stdout/stderr и коды проверенных случаев;
- оставшиеся ограничения и непроверенные случаи.

**Проверка этого руководства:** три полных JSON-примера прошли verifier,
интерпретатор и нативное исполнение; patch изменяет максимум с 3 на 12;
намеренно неверное ожидание суммы возвращает 71. Проверено на AIL 0.1.1
в Linux x86-64 2 октября 2026 года.
