# AIL v1: семантика прототипа 0.1

## Представление и идентичность

Основное представление — JSON-объект с обязательными полями `version: 1`, `entry`,
`globals`, `functions`. Неизвестные поля и повторяющиеся ключи JSON запрещены.
Версия формата (`1`) и версия реализации (`0.1.0`) — разные величины.

Все ID соответствуют `[A-Za-z_][A-Za-z_0-9]*`. ID функций уникальны в модуле,
ID globals уникальны в модуле, ID блоков уникальны внутри функции. ID параметров
функции, параметров блоков и результатов инструкций образуют общее пространство
SSA-значений внутри функции и не повторяются. Порядок функций несущественен,
первый блок каждой функции является её входом.

Пример полной программы, возвращающей 42:

```json
{
  "version": 1,
  "entry": "main",
  "globals": [],
  "functions": [
    {
      "id": "main",
      "params": [],
      "return": "i64",
      "effects": [],
      "blocks": [
        {
          "id": "entry",
          "params": [],
          "instructions": [
            {"id": "answer", "op": "const", "type": "i64", "value": 42}
          ],
          "term": {"op": "ret", "value": "answer"}
        }
      ]
    }
  ]
}
```

JSON Schema проверяет структуру. Только `verify`/`ail check` проверяют ID,
типы ссылок, достижимость, dominance и эффекты. Схема намеренно допускает некоторые
сочетания полей, которые отвергает семантический проверяющий код.

## Типы

| Тип | Значения |
|---|---|
| `i64` | Знаковые 64-битные целые, диапазон `−2^63 … 2^63−1` |
| `i1` | Boolean; литералы JSON `true` и `false`, вычисленные значения 0/1 |
| `ptr` | Адрес начала global, полученный через `addr` |

Нет неявных преобразований. `i1` нельзя использовать вместо `i64`. Для выбора
числа по условию используется `select`. Параметры функции и блоков задаются
объектами `{"id":"n","type":"i64"}`. Входная функция модуля не принимает
аргументов и возвращает `i64`. Код завершения процесса — младшие восемь бит
возвращённого значения.

Global имеет вид `{"id":"message","text":"Привет\n"}`. Текст кодируется
строго в UTF-8, без автоматически добавленного завершающего NUL. Встроенные NUL
сохраняются. Для пустой строки backend резервирует один байт, но логическая
длина и длина вывода равны нулю.

## Инструкции

Каждая инструкция имеет `id`, `op`, `type`. Все операнды значений — ссылки
на SSA ID, а не inline-литералы. Таблица перечисляет дополнительные поля.

| `op` | Поля | Семантика и тип |
|---|---|---|
| `const` | `value` | `i64`-литерал в диапазоне или JSON boolean для `i1` |
| `add`, `sub`, `mul` | `args:[a,b]` | `i64 → i64`, переполнение по модулю `2^64` |
| `sdiv`, `srem` | `args:[a,b]` | Знаковое деление / остаток `i64 → i64` |
| `and`, `or`, `xor` | `args:[a,b]` | Одинаковый `i64` или `i1`, результат того же типа |
| `eq`, `ne` | `args:[a,b]` | Одинаковый `i64` или `i1`, результат `i1` |
| `slt`, `sle`, `sgt`, `sge` | `args:[a,b]` | Знаковое сравнение `i64`, результат `i1` |
| `select` | `cond`, `yes`, `no` | `cond:i1`, ветви и результат одного типа |
| `call` | `function`, `args` | Вызов определённой в модуле функции, до 6 аргументов |
| `addr` | `global` | Получить `ptr` на global |
| `write` | `global`, `fd` | Вывести весь global в `fd:i64`, результат `i64`, эффект `io` |
| `syscall` | `number`, `args` | Linux x86-64 syscall, до 6 `i64`/`ptr`, результат `i64` |

Итого 20 opcode. Инструкция `select` выбирает из уже вычисленных значений и
не является ленивой веткой. Для условного выполнения побочных эффектов нужен
терминатор `branch`.

`sdiv` округляет частное к нулю. Остаток равен `a − quotient × b` и имеет знак
делимого или равен нулю. Деление на ноль и пара `−2^63 / −1` вызывают ловушку:
нативная программа завершается с кодом 125. То же правило применяется к `srem`,
включая пару `−2^63 % −1`. Интерпретатор поднимает `ArithmeticTrap`, сохраняя
предшествующий вывод в полях `stdout` и `stderr`. CLI интерпретатора дополнительно
пишет диагностику ловушки в stderr; нативная программа завершается без неё.

`write` выполняет один системный вызов `write(2)`: не повторяет запись при
частичном результате или `EINTR`; возвращает реальное число записанных байт либо
отрицательный Linux errno. Оно вычисляет длину только из конкретного global,
поэтому сама эта инструкция не читает произвольный диапазон памяти. Интерпретатор
моделирует успешную запись stdout/stderr; другие fd возвращают `−9` (`EBADF`).
Это модель для сравнения малых программ, а не точная эмуляция состояния ОС.

Raw `syscall` требует **обоих** эффектов `io` и `unsafe`. У него нет списка
разрешённых номеров, проверки адресов или sandbox. Неиспользуемые регистры
аргументов backend обнуляет. Интерпретатор отказывается исполнять эту инструкцию.

## Управление потоком и SSA

Блок содержит `id`, массив `params`, массив `instructions` и ровно один `term`.
Входной блок не имеет параметров блока; переходы в него запрещены. Все блоки
должны быть достижимы из входного блока. Параметры функций доступны во всех блоках.

Терминаторы:

```json
{"op":"ret","value":"answer"}
```

```json
{"op":"jump","target":"loop","args":["next_n","next_acc"]}
```

```json
{
  "op":"branch",
  "cond":"done",
  "then":{"target":"exit","args":["acc"]},
  "else":{"target":"body","args":["n","acc"]}
}
```

Число и типы аргументов каждого перехода должны совпадать с параметрами блока.
Условие ветвления имеет тип `i1`. Параметры блока получают переданные значения
**одновременно**. Например, переход в тот же блок с аргументами `[b,a]` действительно
меняет `a` и `b` местами. Backend сначала сохраняет все аргументы во временные
стековые слоты, затем записывает все параметры назначения.

Определение значения должно доминировать его использование: каждый путь от
входа до места использования проходит через определение. Внутри блока инструкция
может ссылаться только на параметры и предыдущие инструкции. В аргументах
перехода проверяется доступность на исходящем ребре. Значение, определённое только
в одной ветке, нельзя использовать после слияния без передачи через параметр.

SSA означает однократное **статическое** определение, а не однократное выполнение:
инструкция в цикле может исполняться много раз.

## Эффекты функций

`effects:[]` означает отсутствие объявленного I/O и unsafe-операций. Возможны
`io`, `unsafe`; неизвестные и повторяющиеся эффекты запрещены. Функция должна
объявить эффекты каждой инструкции и всех вызываемых функций. Объявлять лишний
эффект разрешено. Рекурсивные функции проверяются по заявленным сигнатурам.

`pure` — не отдельный opcode или effect. Пустой список не гарантирует завершение,
ограниченное потребление ресурсов или отсутствие арифметической ловушки.

## ABI и сборка

Backend реализует целочисленную часть System V AMD64 calling convention:
аргументы `rdi,rsi,rdx,rcx,r8,r9`, результат `rax`, сохранение `rbp`, выравнивание
`rsp` на 16 байт перед `call`. Значения хранятся в восьмибайтовых слотах стека.
Функции не экспортируются как публичный FFI-интерфейс этой версии.

Linux syscall convention: номер в `rax`, аргументы `rdi,rsi,rdx,r10,r8,r9`,
результат в `rax`, `rcx/r11` считаются испорченными. `_start` вызывает входную
функцию и затем `exit(60)`. Используется ELF64 `EM_X86_64`, без dynamic loader,
с неисполняемым стеком. PIE, ASLR для сегментов этого бинарника и debug info
не реализованы.

Файл ELF записывается атомарной заменой только после успешной сборки. Предыдущий
output сохраняется при невалидном графе или ошибке assembler/linker.

## Проверяемые изменения

Fingerprint — SHA-256 UTF-8 сериализации `json.dumps(module, ensure_ascii=False,
sort_keys=True, indent=2) + "\n"`. Изменение пробелов и порядка ключей не меняет
fingerprint, изменение порядка элементов массива меняет.

Patch имеет `expected_sha256` и `edits`. Поддерживаются:

```json
{
  "op":"replace_instruction",
  "function":"main",
  "block":"entry",
  "id":"a",
  "value":{"id":"a","op":"const","type":"i64","value":8}
}
```

```json
{"op":"replace_function","id":"main","value":{"id":"main","params":[],"return":"i64","effects":[],"blocks":[]}}
```

Второй фрагмент показывает поля операции: его пустое `blocks` нужно заменить
реальной функцией, иначе verifier его отвергнет. Replacement сохраняет ID цели.
Каждая промежуточная версия графа проверяется, поэтому для изменения нескольких
зависимых инструкций с временно невалидными связями используется замена всей
функции. Оригинальный объект не меняется; невалидная последовательность не
записывается. Fingerprint защищает от ошибочной версии входа, но не заменяет
межпроцессный lock: конкурентная запись другого процесса между чтением файла
и `os.replace` не отслеживается.
